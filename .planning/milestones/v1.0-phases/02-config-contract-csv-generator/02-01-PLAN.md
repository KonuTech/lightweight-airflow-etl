<objective>
Prove the phase's config-contract + business-row-generator architecture end-to-end for ONE
dataset (`customers`): a frozen, `extra="forbid"` Pydantic v2 config tree
(`csv_processor.config.models`), a `load_config()` that merges `configs/defaults.json` with a
per-dataset override and never lets a raw `pydantic.ValidationError` escape (CONFIG-01,
CONFIG-02), and a deterministic Faker + `random.Random(seed)` CLI generator
(`generator/generate_csv.py`, GEN-01) that reads that same validated config and writes a real
CSV fixture to `./data/customers/`. This is this phase's tracer: after this plan, a developer can
run one command and get a real, config-validated CSV file on disk — end to end, no stubs.

Purpose: prove the config-schema-to-generated-fixture pipeline works correctly for one dataset
before the phase commits to the same shape for `orders` (Plan 02) and before authoring the much
larger, independent fixture-corpus subsystem (Plans 03-05) that Phase 3 will test its detection
code against.
Output: a working `csv_processor.config` package, two dataset-agnostic config files
(`configs/defaults.json`, `configs/datasets/customers.json`), a working `generator/generate_csv.py`
CLI, the project's first `pytest` infrastructure (Wave 0 gap closed), and a real generated CSV at
`./data/customers/customers_<today>.csv`.
