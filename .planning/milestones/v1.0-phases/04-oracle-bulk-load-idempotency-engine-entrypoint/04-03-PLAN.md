<objective>
Fix 04-REVIEW.md's BLOCKER CR-01: `csv_processor.engine.process()` crashes with an unhandled
`AttributeError` instead of returning `ProcessingResult(status=Status.DATABASE_ERROR)` when
`load.get_connection()` itself fails (Oracle down, bad credentials, network unreachable). The
`except oracledb.Error:` branch (engine.py:297-298) unconditionally calls `connection.rollback()`
while `connection` can still be `None` at that point, since `connection = load.get_connection()`
is the very first statement inside the `try` block and is never rebound on failure. Verified
empirically in 04-REVIEW.md against the real installed `oracledb==4.0.2`: `oracledb.connect()`
failures raise `oracledb.OperationalError`, a subclass of `oracledb.Error` -- a real, reachable
path, not theoretical.

Also folds in WR-01 (same unguarded-`rollback()` pattern in the `except StructuralValidationError:`
branch, engine.py:294-296 -- safe today only by incidental call order, not by any local guard) since
the fix touches the identical code shape and it would be inconsistent to leave one branch fixed and
the other fragile.

Purpose: Restore `process()`'s documented contract -- "a `ProcessingResult` with exactly one of the
7 closed `Status` values -- never raises" (ENGINE-08) -- for the single most ordinary Oracle failure
mode (connection cannot be opened), which is the one path this phase's otherwise-thorough test suite
never exercised (WR-05).

Output: `engine.py`'s two unguarded `connection.rollback()` call sites are guarded on
`connection is not None`, and a new regression test in `tests/unit/test_engine_process.py` proves a
real `oracledb.Error` from `load.get_connection()` now yields `DATABASE_ERROR` instead of crashing.

Out of scope (04-REVIEW.md warnings/info intentionally NOT touched by this plan, still open):
WR-02 (`ColumnSpec` doesn't forbid a stray `format` field on non-date/timestamp columns), WR-03
(Oracle credential env-var fallback is silent, no warning log), WR-04 (`process()`'s cursor is never
explicitly closed, relying on connection-close cleanup), IN-01 (the general pattern of suppressing
type-checker signals with `# type: ignore` elsewhere in the codebase). Do not implement fixes for
these here -- they dilute focus from the one real crash bug this plan closes.
</objective>
