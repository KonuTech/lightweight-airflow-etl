<objective>
Close UAT gap G-01-1: a fresh `make up`/`make smoke-test` cold start can hit a `ConnectionResetError`
raw traceback in `scripts/verify_environment.py`, because (1) `airflow-apiserver` and its sibling
services have no `healthcheck:` in `docker-compose.yml` so `docker compose up -d --wait` falsely
reports them Healthy the instant the container starts (not once the app is actually serving), and
(2) `verify_airflow_auth()`'s exception handling structurally cannot catch the `ConnectionResetError`
raised during urllib's response-read phase, only during the connect/send phase (WR-03's URLError
fix, commit d7d0882, was scoped to the wrong phase for this specific race).

Purpose: both root causes are independently confirmed in `.planning/debug/apiserver-auth-connreset.md`
via direct evidence (docker inspect, log-timestamp correlation, urllib source inspection, and a
604-attempt polling reproduction) -- this plan implements both of the debug session's own
recommended fix directions so the cold-start race is closed at the infrastructure layer (real
readiness signal) and defensively at the client layer (retry a bounded, evidence-backed race window
instead of crashing on it).

Output: `docker-compose.yml` with real healthchecks on all four Airflow services; broadened,
retry-with-backoff exception handling in `scripts/verify_environment.py`; a new
`tests/test_verify_environment.py` regression test proving the retry/clean-failure/no-retry-on-
HTTPError behavior deterministically.
</objective>

| Developer running `make verify` <-> Airflow apiserver over loopback HTTP | `verify_airflow_auth()`'s retry loop is a local dev-only diagnostic client, not a production auth path |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Denial of Service (delayed failure signal) | `verify_airflow_auth()` retry-with-backoff loop | low | accept | Retry budget is bounded (6 attempts, ~23s worst case) and evidence-based (2.3x the empirically measured 12.66s cold-start gap) -- a genuinely down apiserver still fails within a bounded, documented window, not indefinitely; genuine auth rejections (HTTPError) are explicitly excluded from the retry path and fail immediately (Task 2's `<prohibitions>`) |
| T-01-08 | Tampering | `docker-compose.yml` healthcheck `CMD-SHELL` strings using `$$HOSTNAME` | low | accept | `$$HOSTNAME` resolves to the container's own hostname (Docker-assigned, not attacker- or user-controlled input) inside a `CMD-SHELL` that only runs `airflow jobs check` -- no external data reaches the shell string |
| T-01-09 | Information Disclosure | `AssertionError` messages surfaced by `verify_airflow_auth()` on retry exhaustion, printed to local stderr | low | accept | This is a local, developer-run diagnostic script (`make verify`), not a production/network-facing service; the underlying exception text contains no secrets (network error strings only, no credentials) |
