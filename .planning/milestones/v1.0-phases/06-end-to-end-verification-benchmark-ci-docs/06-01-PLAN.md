<objective>
Build the automated end-to-end proof that TEST-03 requires: an HTTP request triggers the real
`csv_ingest` DAG, the deferred `wait_for_file` sensor genuinely wakes (not polls) once a fixture
file appears, `process_csv_task` runs the real CSV engine, and correct/incorrect rows land in
Oracle's `customers_valid`/`customers_invalid` tables — asserted via a real `oracledb` query, not
`DagRun.state` alone (D-08).

This is Phase 6's tracer: the thinnest slice that touches every layer the phase modifies
end-to-end (HTTP -> Airflow REST -> deferred trigger -> `csv_processor.engine.process()` ->
Oracle), wired for real against the already-proven `docker-compose.yml` stack, with a real
runnable `<verify>`. Everything else in Phase 6 (benchmark, CI, evidence, docs) builds outward
from this proven slice.

Purpose: TEST-03 is currently only proven manually (`docs/airflow-dag.md`'s "Live Verification
Evidence" section, captured by hand in Phase 5) — this plan automates that same proof into a real,
repeatable `pytest` suite.
Output: `scripts/dag_polling.py` (reusable Airflow REST polling helpers), `tests/e2e/` package
with a real, passing end-to-end test, and fast unit coverage for the polling helpers.
</objective>
