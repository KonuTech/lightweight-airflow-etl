<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Forked-repo PR -> `lint-type-unit`/`oracle-e2e` jobs | Untrusted PR code runs in both jobs; neither job may hold write access or repo secrets |
| Third-party GitHub Actions (`astral-sh/setup-uv`, `actions/checkout`) -> CI runner | A compromised/malicious action version could run arbitrary code in the job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-06-02 | Tampering | `.github/workflows/ci.yml` (`astral-sh/setup-uv`, `actions/checkout`) | high | mitigate | Pin the exact, live-verified immutable tags (`actions/checkout@v7.0.1`, `astral-sh/setup-uv@v10.0.1`) rather than floating `@v7`/`@v10` — confirmed still current via GitHub's own Releases API this phase's research pass |
| T-06-03 | Elevation of Privilege | `.github/workflows/ci.yml` trigger | high | mitigate | `on: pull_request:` only, never `pull_request_target` — a forked-repo PR never gains base-repo write access or secrets under `pull_request`'s default GitHub semantics; no `permissions: contents: write` (or any write scope) anywhere in this file, since neither job needs it |
| T-06-05 | Denial of Service (CI disk exhaustion) | `oracle-e2e` job's `docker compose up` | low | accept | This project's own measured ~14.8GB image+volume footprint (docs/environment.md) could exceed a GH-hosted runner's free disk headroom (Assumption A2, unconfirmed) — accepted as a "watch for it" risk per Pitfall 5's own guidance, with the `slim-faststart` Oracle tag documented as a fallback rather than pre-emptively switched |
| T-06-06 (part of P3 above) | Repudiation | Branch Protection status-check enforcement | high | mitigate | A red `oracle-e2e`/`lint-type-unit` check must actually block merge, not just display — this requires the separate, documented, manual Branch Protection configuration step (Pitfall 6, human-check above); flagged explicitly rather than silently assumed satisfied by the workflow YAML alone |

</threat_model>
