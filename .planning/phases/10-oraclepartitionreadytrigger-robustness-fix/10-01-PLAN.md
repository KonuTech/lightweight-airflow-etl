```python
    async def run(self) -> AsyncIterator[Any]:
        retry_count = 0
        while True:
            try:
                connection = await oracledb.connect_async(
                    user=oracle_user(), password=oracle_password(), dsn=oracle_dsn()
                )
                try:
                    cursor = connection.cursor()
                    await cursor.execute(_POLL_QUERY)
                    (count,) = await cursor.fetchone()
                finally:
                    try:
                        await connection.close()
                    except oracledb.Error:
                        _LOGGER.debug(
                            "connection.close() failed on an already-broken connection",
                            exc_info=True,
                        )
            except oracledb.OperationalError as exc:
                retry_count += 1
                if retry_count > _MAX_TRANSIENT_RETRIES:
                    raise
                delay = min(
                    _RETRY_BASE_DELAY_SECONDS * (2 ** (retry_count - 1)),
                    self.poke_interval,
                )
                _LOGGER.warning(
                    "Oracle poll attempt %d/%d failed (transient): %s -- retrying in %.1fs",
                    retry_count,
                    _MAX_TRANSIENT_RETRIES,
                    exc,
                    delay,
                )
                await asyncio.sleep(delay)
                continue

            retry_count = 0  # a successful poll clears the transient-failure budget
            if count >= _BOTH_DATASETS_PRESENT:
                yield TriggerEvent({"status": "ready"})
                return
            await asyncio.sleep(self.poke_interval)
```

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `OraclePartitionReadyTrigger.run()` ↔ Oracle Database (network) | The trigger polls an external Oracle instance via `oracledb.connect_async()`; connectivity/query failures from that boundary cross into this phase's exception-handling code as `oracledb.*Error` instances |
| `run()`'s exception log lines ↔ Airflow's task-log stream | `_LOGGER.warning(...)`/`_LOGGER.debug(...)` write `str(exc)` into Airflow's own trigger-log output (not an external sink) -- the only place exception content is ever persisted by this phase's new code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-10-01 | Information Disclosure | `_LOGGER.warning("Oracle poll attempt %d/%d failed (transient): %s ...", ..., exc, ...)` (D-07) | mitigate | Log only `str(exc)` via `%s` and `exc_info=True` to Airflow's own task-log stream, never an external sink -- matches this project's existing logging convention. Residual risk (10-RESEARCH.md Assumptions Log A1, unverified): whether `oracledb.OperationalError`'s `str()` could ever embed the plaintext Oracle password. Flagged as a spot-check during Task 2's test-writing (the literal exception messages used in the new tests, e.g. `"DPY-6005: cannot connect"`, are drawn from the driver's real DPY-/ORA- code format, which does not embed credentials) -- not a blocker for this phase. |
| T-10-02 | Denial of Service | The retry loop inside `run()` (D-03) | mitigate | Bounded cap of exactly 10 consecutive `OperationalError` failures before re-raising (`_MAX_TRANSIENT_RETRIES = 10`) -- prevents an indefinitely-retrying deferred task from consuming the triggerer's shared event loop forever; verified by `test_run_reraises_after_exhausting_transient_retries`. |
| T-10-03 | Tampering / Repudiation | The `except` clause scope in `run()` (D-02) | mitigate | Only `oracledb.OperationalError` is caught for retry; every other `oracledb.Error` subclass (e.g. `ProgrammingError` from a broken query or dropped/renamed table) propagates immediately uncaught, preserving the traceback as evidence rather than being silently retried or masked -- verified by `test_run_propagates_non_transient_error_immediately`. |
| T-10-04 | Repudiation | The `finally: await connection.close()` block (D-06) | mitigate | A close-time failure on an already-broken connection is caught in its own nested `try/except oracledb.Error`, logged at `debug`, and never re-raised -- the original, more diagnostic exception (evidence of the real failure) is what continues to propagate, never overwritten -- verified by `test_run_close_failure_does_not_mask_original_exception`. |
