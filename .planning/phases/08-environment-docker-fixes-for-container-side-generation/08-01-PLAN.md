<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Host filesystem (`./data`, `./docker/airflow/simple_auth_manager_passwords.json.generated`) ↔ `airflow-init` container | `airflow-init` runs as root (`uid 0`) inside the container, against host-bind-mounted paths, before any non-root Airflow service starts |
| `.env`-sourced `${AIRFLOW_UID}` value ↔ shell command interpolation | The only variable interpolated into the root-run `bash -c` command is sourced from this project's own local, developer-controlled `.env` file — not user/network input |
| PyPI registry ↔ Dockerfile `pip install` | `faker==40.37.0` is a new package pulled into the image at build time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-08-01 | Tampering | `airflow-init`'s `chown -R`/`rmdir`/`mkdir -p` shell block | mitigate | Scope every `chown -R`/`mkdir -p`/`rmdir` to exact literal paths (`/opt/airflow/data`, the single passwords-file path) copied verbatim from RESEARCH.md's drafted command — never a wildcard, glob, or parent-directory chown. `rmdir` (not `rm -rf`) only ever removes an empty, wrongly-typed auto-created directory, never real content. |
| T-08-02 | Elevation of Privilege | `airflow-init` service running as `user: "0:0"` (root) | mitigate | Root scope limited to exactly one service, gated by the pre-existing `depends_on: service_completed_successfully` chain so it runs once and exits before any non-root service starts. The only interpolated shell variable is `${AIRFLOW_UID:-50000}`, sourced from this project's own local `.env` (developer-controlled, not user/network input). |
| T-08-03 | Information Disclosure | Passwords-file permission bits after repair | mitigate | `chmod 664` (owner+group read/write, no other-write), not `666` (world-writable) — tightest mode that still lets the container's `uid 50000` owner read/write it. This stack is already `127.0.0.1`-bound local-dev-only (accepted INFRA-03 scope), so residual group-readability exposure is accepted, not further mitigated. |
| T-08-04 | Tampering | Unconditional overwrite of an existing, already-generated passwords file on every `airflow-init` run | mitigate | Guard the seed step with "only write default content if the file doesn't already exist" — a real, already-generated password (or a developer's manual edit) is never silently stomped on a routine restart. |
| T-08-SC | Tampering (supply chain) | `faker==40.37.0` pip install | accept (already vetted) | Fully vetted in 08-RESEARCH.md's Package Legitimacy Audit (PyPI, `joke2k/faker`, slopcheck `[OK]`, disposition **Approved**) — no blocking human-verify checkpoint required since disposition is Approved, not `[ASSUMED]`/`[SUS]`/`[SLOP]`. Version pinned exactly to the root `uv.lock` value, no drift risk. |

</threat_model>
