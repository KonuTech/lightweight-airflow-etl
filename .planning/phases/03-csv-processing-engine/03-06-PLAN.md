<objective>
Close the two Critical gaps `03-VERIFICATION.md` found in Phase 3's already-executed, already-shipped
`source.py`/`engine.py`: (1) `ColumnSpec.required` is parsed but never enforced — every declared
column is treated as mandatory regardless of its `required` flag, so `customers.json`'s own
`signup_country` (`required: false`) can never actually be absent from a file without a false
`MISSING_REQUIRED_COLUMN` whole-file reject; (2) `detect_header()`'s computed
`header_row_index`/`footer_row_indices`/`repeated_header_row_indices` are silently discarded by
`prepare_source()`'s PASS-2 real read, which only ever skips exactly one hardcoded row — a genuine
preamble line, footer line, or repeated interior header row gets fed straight into row-level
validation as ordinary data. Both bugs are isolated to `source.py`; fixing gap 1 alone would also
introduce a `KeyError` in `validate.check_row()`/`normalize_row()` the moment an optional column is
genuinely absent, so `engine.py`'s row-dict construction is fixed alongside it. A third, low-risk
Warning finding (`detect/filename.py`'s residual `dataplat` import, CLAUDE.md's never-import rule) is
folded in as a small third task since it is a one-line-cause fix with a real, currently-untested
consumer function.

Purpose: `03-VERIFICATION.md` scored this phase 8/10 truths verified, with both failures traced to
this same file/function pair — closing them restores full goal achievement for Phase 3 (structural
validation must be correct against the project's own shipped `customers.json`, not just against the
corpus fixtures that happened not to exercise these two paths) before Phase 4 builds Oracle loading on
top of `process_chunks()`.
Output: `source.py`'s header-vs-config check correctly reads `column.required`; PASS 2 correctly
excludes preamble/footer/repeated-header rows; `engine.py` never KeyErrors on an absent optional
column; two new regression tests close the exact gaps `03-VERIFICATION.md`/`03-REVIEW.md` (CR-01/CR-02)
identified; `detect/filename.py` has zero `dataplat` import.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Untrusted CSV file content → `source.py`'s header-vs-config check | Which columns are "missing" is now partly driven by a per-column boolean read from Pydantic-validated `config.json`, not row content — still a config-author-controlled input, never CSV-content-controlled |
| Untrusted CSV file content → `source.py`'s preamble/footer/repeated-header exclusion | A crafted file's row shapes directly influence which rows `detect_header()` classifies as footer/repeated-header and therefore silently excludes from processing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Tampering | `source.py`'s `required_names` filter | medium | mitigate | Reads directly from Pydantic-validated, frozen `ColumnSpec.required` (validated once at config-load time per CONFIG-02) — never re-derived from row content; a malicious CSV cannot influence which columns count as required, only a `config.json` author can |
| T-03-10 | Tampering | `source.py`'s footer/repeated-header exclusion runs only against the bounded 64 KiB PASS-1 sample | low | accept | `detect_header()` only sees rows within `SAMPLE_BYTES` (64 KiB, ENGINE-07's memory-bound design); a footer/repeated-header row physically beyond that sample boundary in a very large file is not detected/excluded. Pre-existing limitation of the vendored `detect_header()` design (not introduced by this fix) — extending detection to the whole file would violate ENGINE-07's bounded-memory guarantee and is out of this gap-closure's scope; flagged for visibility only |
| T-03-11 | Tampering | `detect/filename.py`'s new local `FilenameMaskConfig` | low | mitigate | Has zero dependency on the forbidden reference-package import — eliminates the risk of a `dataplat` coupling resurfacing (CLAUDE.md's never-import rule) the moment a type-checker or a future caller exercises `parse_filename()` |
