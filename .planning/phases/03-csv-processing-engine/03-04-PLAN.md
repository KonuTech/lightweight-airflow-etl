<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Untrusted .gz/.zip file bytes → compression.py | The single riskiest new trust boundary this phase introduces — a crafted archive is a classic decompression-bomb / zip-bomb vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Denial of Service | Decompression bomb (small `.gz`/`.zip` expanding to unbounded size) | high | mitigate | `_DecompressionBombGuard`'s cumulative-byte ceiling, enforced via bounded incremental reads (never a single unbounded `.read()` call to the underlying decompressor) — proven by a real test with an artificially tiny ceiling |
| T-03-10 | Denial of Service | Zip-bomb via a multi-entry archive | high | mitigate | D-33's "exactly one member" rule rejects any archive with zero or more than one entry before any member is ever opened |
| T-03-11 | Tampering | A corrupted/truncated archive silently producing partial/garbage decompressed content | medium | mitigate | `zipfile.BadZipFile` and any guard-tripped `FileInspectionError` propagate as a whole-file reject via `StructuralValidationError`, never a silently-truncated valid-looking stream |
</threat_model>
