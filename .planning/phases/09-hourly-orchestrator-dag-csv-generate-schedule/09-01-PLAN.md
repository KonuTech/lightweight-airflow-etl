## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-9-01 | Tampering | `retention_sweep()`'s filesystem deletes | mitigate | Full mitigation lands in Plan 09-02, where the DAG task always calls this function with a fixed, hardcoded `paths.DATA_ROOT / dataset` root -- never a runtime-supplied path. This plan's function itself performs no traversal guarding (by design, matching `resolve_matched_file()`'s precedent of trusting `base_dir`), so the boundary is documented here and enforced at the call site. |
| T-9-02 | Denial of Service | A crafted/corrupted filename in `data/{customers,orders}/` causing `retention_sweep()` to raise and abort the retention pass | mitigate | Every per-file operation (date-token parsing, `Path.unlink()`) is wrapped in its own narrow `try/except` (`ValueError`, `OSError`) inside `retention_sweep()` itself -- proven by `test_retention_never_raises` -- so one bad entry can never prevent the rest of the sweep or propagate up to fail the DagRun (D-18). |
| T-9-03 | Information Disclosure | Function argument/return values (file paths, row counts) | accept | No secrets flow through any of these three functions -- file paths under the project's own `data/` tree and plain integer row counts only. |
