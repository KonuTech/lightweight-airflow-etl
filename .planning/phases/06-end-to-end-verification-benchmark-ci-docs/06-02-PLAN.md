    `[c.name for c in config.columns]`, re-validates `table`/every column name via
    `is_safe_identifier()` first (mirrors `load.insert_rows()`'s own defense-in-depth check,
    D-04/T-04-01's established pattern applied here too), then loops
    `for row in chunk_valid: cursor.execute(sql, row)` — genuinely one `execute()` call per
    row, NEVER `cursor.executemany()` at any chunk size (D-01's exact requirement; this is

    `--dataset`/`--rows`/`--seed` flag shape) with `--mode {naive,bulk}` selecting which
    write path a single process invocation exercises; connect once via
    `csv_processor.load.get_connection()`; before writing, `DELETE FROM
    {config.oracle.valid_table}` and `DELETE FROM {config.oracle.invalid_table}` so repeated
    runs start from a clean, comparable table state (commit this delete before timing
    starts, not counted in Oracle load time); iterate
    `for chunk_valid, chunk_invalid in process_chunks(file_path, config):` calling either
    `run_naive(cursor, config, chunk_valid)` (mode=naive) or
    `load.insert_rows(cursor, table=config.oracle.valid_table,
