## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args -> file writes | `--dataset`/`--correlated`/`--rows`/`--seed` are developer-supplied CLI args, not untrusted network input — local-dev-only scope |
| Staging dir -> watched dir rename | Same-filesystem `Path.rename()`, no network/cross-mount boundary crossed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02-01 | Denial of Service | `write_staged()`'s staging directory left uncleaned on a crash mid-write | low | accept | A crash between `write_csv()` and `rename()` leaves an orphaned file under `.staging/`, invisible to the non-recursive `FileSensor` glob (confirmed in RESEARCH.md Pattern 4) — no functional impact, at most a small amount of disk left behind in a local-dev-only environment; not worth adding cleanup-on-crash machinery for |
| T-07-02-02 | Tampering | `parser.error()` path for the blocked `--dataset orders` CLI mode | low | accept | Argparse's own `.error()`/`sys.exit(2)` — no new code path handling untrusted input, purely a local CLI usage guard |
</threat_model>
